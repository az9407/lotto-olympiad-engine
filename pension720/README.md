# 연금복권720+ 후보 15개 엔진

역대 당첨번호 엑셀로 다음 회차 후보 15개를 고르는 패턴 퍼즐 엔진입니다. 로또 6/45 엔진과는 별개입니다.

## 실행

Python 3.10 이상, numpy 2.0 이상, openpyxl이 필요합니다.

```
python -m pip install -r requirements.txt
python pension720/predict_pension15.py
```

- 인자를 생략하면 `pension720/data/당첨번호.csv`를 씁니다. 다른 엑셀이나 CSV를 쓰려면 경로를 붙입니다.
- 엑셀에는 `당첨번호` 시트와 `회차, 추첨일, 1등 조, 1등 번호, 보너스 번호` 열이 있어야 합니다.
- 새 회차 행을 추가하고 다시 돌리면 목표가 마지막 회차 + 1, 마지막 추첨일 + 7일로 바뀝니다.
- 번호 칸이 숫자로 바뀌어 앞자리 0이 사라져도 6자리로 복원합니다.
- 결과는 `pension720/results/round_<목표회차>/`에 `결과.md`, `후보15.csv`, `적용규칙.csv`로 저장됩니다.
- 실행 시간은 3분 안팎입니다.

## 매주 자동 실행

`.github/workflows/pension720-weekly.yml`이 목요일 19:45부터 금요일 09:20 KST까지 다섯 번 `weekly.py`를 돌립니다. 이미 보낸 회차면 바로 끝납니다.

1. 동행복권 공식 API, 막히면 nostra-data 공개 저장소에서 새 회차를 받아 `data/당첨번호.csv`와 `data/연금복권720_역대당첨번호.xlsx`에 추가합니다. 두 출처가 다르면 멈춥니다.
2. 방금 나온 번호를 지난주 모델로 분석해 `results/round_<그 회차>/분석.md`에 씁니다. 500만 중 점수 순위, 충족·빗나간 규칙, 지난주 후보 10개의 등수.
3. 주간 학습 `learn.py`
   - 1단계 엔진 다듬기: 지금 엔진 설정과, 시간 가중치·문턱·수축·규칙 상한·같은 변수 개수·자리 배율·1등:보너스 비율 중 하나나 둘을 바꾼 설정 23개를 최근 60회로 겨룹니다.
   - 2단계 공식 고르기: 다듬은 엔진, `formulas.py`·`lab.py`의 다른 공식 약 530개, 앙상블 6개를 같은 60회로 겨룹니다.
   - 각 회차는 그 이전 자료로만 학습합니다. 지금 쓰는 것보다 회차별 짝 비교에서 평균 순위 2,000 이상 낮고, 표준오차의 Z배 넘게 나을 때만 바꿉니다. Z는 도전자가 많을수록 커져서 우연히 통과할 확률이 5%로 묶입니다. 도전자 23개면 약 3.1, 560개면 약 3.9입니다.
   - 결과는 `결과.md`의 주간 학습 표와 `학습.txt`, 쓴 공식은 `방법.txt`에 남습니다.
4. 지난주 방법이 실제 1등을 500만 중 몇 위에 놓았는지 `results/실전성적.csv`에 매주 쌓습니다. 이것만이 미리 정해 둔 방법의 진짜 성적입니다.
5. 다음 회차 후보를 계산해 `results/round_<다음 회차>/`에 저장하고, 10개와 분석·학습 요약을 텔레그램 @lotto_pension_bot 으로 보냅니다. 보낸 글은 `텔레그램.txt`로 남습니다.
   - 10개는 15개의 앞 10개가 아니라 `후보10.csv`로 따로 고릅니다. 끝자리 0~9가 한 번씩 들어가 7등 이상 하나는 매주 반드시 맞고, 끝 2·3자리도 모두 달라 6등·5등 이상이 하나라도 걸릴 확률이 10장으로 낼 수 있는 최대인 10%·1%가 됩니다.
6. 금요일 실행까지 새 회차를 못 받으면 텔레그램으로 한 번 알립니다.

필요한 설정: 저장소 Settings → Secrets and variables → Actions에 `TELEGRAM_BOT_TOKEN`. 대화방은 봇에 /start를 보낸 개인 대화방을 처음 실행 때 찾아 `data/telegram_chat.enc`에 봇 토큰 기반 키로 암호화해 둡니다.

손으로 돌리기: `python pension720/weekly.py --no-send` 는 텔레그램 없이 출력만, `--no-fetch` 는 새 회차를 받지 않습니다.

## 공식 후보군

`formulas.py`에 규칙 엔진과 다른 방식의 공식들이 있습니다. 빈도, 냉각, 미출현, 이월, 마르코프 전이, 이웃 자리쌍, 특징 빈도, 유사회차, 로지스틱 회귀, 무작위 기준. `formula_search.py`로 한꺼번에 걷기 검증합니다.

```
python pension720/formula_search.py --folds 100 --null 5
```

`--null`은 같은 길이의 가짜 무작위 자료에서도 공식들을 돌려, 공식을 여러 개 시험할 때 우연만으로 최고 공식이 몇 %까지 나오는지 함께 보여 줍니다. 결과는 `results/공식후보/`에 저장됩니다.

`lab.py`는 공식을 531개로 넓힌 실험실입니다. 자리별 숫자·자리합·조·6자리 값·보너스를 차트로 보고 이동평균·모멘텀·되돌림·볼린저·피보나치·일목·AR·푸리에·RSI·MACD·돌파를 쓰는 공식, 원·달러·엔·위안·유로·유가·S&P500·금의 변화와 RSI·이평 교차로 나눈 매크로 국면, 달력·달 위상 국면, 시차 마르코프, 미출현 위험률, 여러 닮은 회차, 그래디언트 부스팅, 상위 공식 쌓기까지 들어 있습니다. 개발 100회에서 고르고 처음 보는 40회로 검증합니다.

```
python pension720/lab.py --null 2
```

매크로 값은 `data/macro.csv`에 있고, 주간 실행 때 datasets 공개 저장소에서 새로 받아 합칩니다. 각 추첨일 전날까지 나와 있던 값만 씁니다. 월간 값은 35일 늦춰 씁니다.

## 방법

1. 규칙 후보: 6자리 숫자의 자리값·나머지·합·홀짝·인접차, 1~3회 전 1등·보너스와의 관계, 숫자별 미출현 주기, 날짜·회차와의 나머지 관계를 사건으로 만듭니다. 상시 규칙은 B, 선행조건이 붙은 규칙은 A입니다.
2. 채택 기준: 그 시점 이전 자료에서 전체 30회·최근 100회 중 10회·최근 40회 중 4회 이상 적용됐고, 세 구간 모두 적중률이 문턱 이상이며, 500만 후보 중 통과 비율이 50% 이하인 규칙만 씁니다. A 규칙은 통과 비율 40% 이상만 씁니다.
3. 가중치: 시간 가중 적중률을 기저 통과율 쪽으로 수축한 뒤 `logit(수축 적중률) − logit(기저 통과율)`. 끝자리에 가까운 자리 규칙은 1.1~1.5배.
4. 정리: 가중치 순으로 담되 같은 변수는 2개까지, 이미 담은 규칙과 전수 상관 0.5 이상이면 중복, 동시 성립률이 기대치의 80% 미만이면 모순으로 빼고 상한 개수에서 멈춥니다.
5. 점수: 1등 모델과 보너스 모델 각각 500만 후보 균등분포 기준 z 점수로 바꾸고 `S = 0.8 × 1등 z + 0.2 × 보너스 z + 0.000001 × 자리별 빈도 로그`. 마지막 항은 동점 정리용입니다.
6. 설정 고르기: 시간 가중치·문턱·수축·상한 16개 조합을, 최근 40회 각각을 그 이전 자료로만 학습해 무작위 20만 후보 안에서 실제 1등의 평균 순위로 비교합니다.
7. 선정: 점수순으로 내려가며 같은 자리 일치 3개 이하, 앞 5자리 자리별 같은 숫자 4회 이하, 끝 2자리 중복 없음, 끝자리 0~9와 1~5조 모두 포함, 끝자리 최대 2회, 조 최대 4회, 표시 점수 동점 없음을 만족하는 후보를 15개 고릅니다.

점수는 규칙을 고르는 순위 점수일 뿐 당첨 확률이 아닙니다.

## 코덱스 버전에서 바뀐 점 (2026-11-06, Claude)

- 1,503줄 68KB → 1,211줄 55KB. 엑셀 XML 직접 파싱, 결과 ZIP 묶기, 제외 규칙 감사 CSV, 큰 정수 비트 캐시 등 결과에 영향 없는 코드를 걷어냈습니다.
- 보너스 모델에서 조 관련 규칙을 뺐습니다. 보너스 번호는 각조 공통이라 조와 무관한데, 기존 코드는 보너스 이력에 1등 조를 붙여 학습했습니다. 과거 롤링 회차 일부의 보너스 모델에 이 규칙이 들어가 있었고, 341회 후보와 선택 설정은 바뀌지 않았습니다.
- 과거 회차의 날짜는 앞 회차 + 7일 대신 실제 추첨일을 씁니다. 지금까지는 모두 7일 간격이라 결과가 같습니다.
- 결과를 ZIP 대신 `results/round_<회차>/` 폴더에 저장하고, 결과.md에 설정 16개의 롤링 평균 순위를 함께 적습니다.
- 위 변경 외 채점 방식은 그대로이며, 340회 엑셀로 돌린 341회 후보 15개와 점수가 코덱스 결과와 소수 8자리까지 같습니다.
